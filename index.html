ML SYSTEMS / RESEARCH PILOT

Adaptive Systems

Can changing the width and storage precision of an embedding reduce inference latency within an accuracy budget?

Source code ↗Experiment contract ↗
Experimental design
A frozen ResNet-18 extracts CIFAR-10 features. Four configurations cross 512 or 128 features with FP32 or INT8 storage. Each configuration has its own ridge classifier, and INT8 features are reconstructed as FP32 before classification.
Measurement
A single outer timer covers preprocessing through prediction on a single-threaded CPU. The harness records p50 and p95 latency and inventories tensor storage. Energy measurement is pending.
Evaluation
The pilot screens configurations against a provisional 1 percentage-point accuracy margin using a paired bootstrap interval. It selects by validation p50 and locks the choice before evaluating the held-out test set.

COMPUTER VISION / WORKING PROTOTYPE

APEX

A Formula 1 car explorer with a webcam-driven exploded view and a trainable temporal gesture pipeline.

Source code ↗
Interaction
Pinches move the model, two open hands scale it, and a two-pinch pull separates the assembly. Gesture changes and hand loss reset the interaction anchors.
ML pipeline
The recorder exports labeled 32-frame landmark sequences. The PyTorch pipeline compares a mean-pooling MLP, a two-layer LSTM, and a temporal Transformer using participant-isolated splits.
Current behavior
The viewer runs on gesture rules. The repository includes the training pipeline and FastAPI inference service. Dataset collection and trained-model validation are pending.

NETWORKS / LIVE TOOL

Subnet Studio

An interactive lab for seeing how an IPv4 prefix determines the address block and its usable hosts.

Open practice lab ↗Source code ↗
Address engine
Calculates masks, network and broadcast addresses, usable host ranges, and capacity for conventional /0–/30 subnets. VLSM exercises allocate the largest requirements first.
Practice interface
A 32-bit explorer shows the network and host boundary. Generated questions provide immediate feedback, progressive hints, and worked solutions.
Verification
The repository checks 1,000 addresses against an independent BigInt implementation and validates 600 generated question sets, including VLSM capacity and overlap.

SOFTWARE VERIFICATION / TEST EVIDENCE

OsdagBridge Testing

A reproducible test harness for the desktop plate-girder design workflow, from input entry through structural analysis.

Baseline evidence ↗Test repository ↗
Harness
A synthetic fixture populates the desktop inputs and triggers Design. The harness captures dictionaries around the backend handoff and records analysis output.
Baseline finding
The completed spawn-worker run produced 50 load cases, 126 nodes, and 225 elements. The handoff reported an 8.4 m deck width while the analysis logged 8.5 m.
Root cause and coverage
The analysis DTO used a 0.50 m default barrier while the layout used 0.45 m for each of two barriers. The repository also records span limits and design-variation checks.

CYBERSECURITY / ARCHITECTURE CONCEPT

CyberTwin

A proposed identity graph for understanding how public signals can combine into an attack surface.

Architecture and roadmap ↗
Graph model
The proposed graph connects identifiers such as usernames and email addresses to public profiles and exposure signals.
Risk review
The concept maps links that could support impersonation or targeted phishing and calls for showing the evidence behind each risk signal.
Development stage
Identity correlation, graph storage, and risk scoring are architecture proposals in the repository roadmap.
